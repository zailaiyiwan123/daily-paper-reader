## 摘要
用户反馈为大型语言模型的持续改进提供了自然监督，但单条消息可能支持多种具有不同泛化范围的行为更改。我们引入了SLIFT，一种基于用户反馈的任务相对视图的选择性自学习框架。SLIFT将每条反馈消息分解为原子组件，并将每个组件相对于原始任务解释为修复（Fix）、细化（Spec）或无效（Null）：即任务有效性要求、兼容的条件特定细化，或没有可靠正向更新方向的内容。为了在适当的范围内纳入每个更改，SLIFT在共享冻结主干上训练两个互补的LoRA适配器：一个通用适配器（Generalist），通过反馈条件下的自蒸馏将修复要求整合到默认行为中；以及一个专家适配器（Specialist），仅观察任务和通用适配器的响应，为适用但未满足的细化要求提供残余指导。无效组件不产生正向更新。在各种主干网络上，SLIFT在MemoryBench和WildFB上均取得了强劲性能，进一步分析深入探讨了其潜在机制。我们在https://anonymous.4open.science/r/SLIFT发布代码。

## Abstract
User feedback offers natural supervision for persistent LLM improvement, but a single message may support multiple behavioral changes with different scopes of generalization. We introduce SLIFT, a selective self-learning framework built on a task-relative view of user feedback. SLIFT decomposes each feedback message into atomic components and interprets each component relative to the original task as Fix, Spec, or Null: requirements for task validity, compatible condition-specific refinements, or content with no reliable positive update direction. To incorporate each change at the appropriate scope, SLIFT trains two complementary LoRA adapters on a shared frozen backbone: a Generalist that consolidates Fix requirements into default behavior through feedback-conditioned self-distillation, and a Specialist that observes only the task and Generalist response to supply residual guidance for applicable, unmet Spec refinements. Null components induce no positive update. Across backbones, SLIFT achieves strong performance on both MemoryBench and WildFB, with targeted analyses further examining its underlying mechanisms. We release our code at https://anonymous.4open.science/r/SLIFT.

## 一、论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：用户在与大语言模型（LLM）交互时产生的自然反馈，如何被转化为**持久性**的模型行为改进，并且每种改进应当以**恰当的范围（scope）**进行泛化。
- **动机**：用户反馈往往是一句话中包含多种信号（如纠错、偏好、新请求），不同信号支持的行为变更具有不同的泛化边界。若将整条反馈视为单一监督信号，可能混淆"哪些内容该学、该学多广"；而现有的标量奖励/偏好方法会压缩丰富反馈的细粒度信息，非参数记忆方法则难以保证向未见请求的迁移。
- **关键观察**：反馈中不同组件的学习角色取决于其与原始任务的语义关系，而非表面形式。因此需要一个"任务相对（task-relative）"的视角来决定：哪些变更应固化为默认行为、哪些应作为条件性细化、哪些不应驱动任何正向更新。

## 二、论文提出的方法论

### 2.1 核心思想：任务相对的反馈分解

- 将每条用户反馈 `u_i` 用冻结主干模型 `M_0` 分解为**原子组件** `C_i = Extract(x_i, y_log_i, u_i)`。
- 每个组件 `c_ij` 根据与原始任务 `x_i` 的关系被归类为三种角色：
  - **Fix（修复）**：所有任务有效回答都必须满足的性质，缺失则任务无效（如事实纠错、长度约束）。
  - **Spec（细化）**：任务兼容但可选的条件性细化，仅在特定情况下适用（如"用厨房类比解释"）。
  - **Null（无效）**：无可靠正向更新方向的内容（如无关请求、冲突指令、纯情绪反应）。
- 判定依据：动作性（是否指定了交付物的具体性质）、兼容性（是否与任务一致）、遗漏标准（遗漏该性质是否导致任务无效）。

### 2.2 双路径选择性学习框架（SLIFT）

- 在共享冻结主干 `M_0` 上训练两个**互补的 LoRA 适配器**，分别对应不同更新范围：
  - **Generalist（通用适配器）**：只处理 Fix 组件。通过**反馈条件自蒸馏（SDPO 的离线变体）**，将"带 Fix 条件的后见分布"蒸馏到"无反馈条件"的模型行为中，并加入一个无反馈行为锚（`λ_B` 权重）防止无关内容被过度修改。损失函数为：
    `L_G = E[ KL(p_G || p_H) + λ_B · KL(p_G || p_B) ]`
    其中 `p_H` 是冻结主干在 Fix 条件提示下的分布，`p_B` 是无反馈分布，`p_G` 是 Generalist 分布。
  - **Specialist（专家适配器）**：只处理 Spec 组件。输入仅为（任务, Generalist 响应 `y_G`），输出 KEEP（不干预）或 APPLY（附带**最小残余指导** `δ`）。训练目标通过监督微调（SFT）完成，使用冻结主干在特权 Spec 信息下构造的离线目标，经 1:1 类别重采样平衡 KEEP/APPLY 样本。
- **Null 组件不产生任何正向更新**。
- **推理流程**：Generalist 先生成默认响应 → Specialist 判定是否干预（仅约 2%-19% 的任务触发 APPLY）→ 若 APPLY，冻结的 Generalist 执行一次残余指导整合，返回最终响应。
- 该设计受互补学习系统（CLS）功能分化的启发：默认行为整合与条件性精修分离，避免将条件证据泛化为默认行为。

## 六、论文的主要结论与发现

1. **SLIFT 在两类基准上均取得最优性能**：MemoryBench 四分区平均 Norm-Score 在两个骨干上分别达到 55.85（Qwen3-8B）和 53.22（Ministral3-14B），显著超过所有基线和消融变体；WildFB 训练后在 IFEval 和 AlpacaEval 2.0 上获得最大提升，MMLU-Pro 基本持平。
2. **分解与任务相对解读是关键**：消融显示，移除原子提取或任务上下文会导致最大性能下降，证明复合反馈必须分解、且角色判定必须参照原始任务。
3. **Spec 不应走 Generalist 通路**：将 Spec 与 Fix 合并训练或直接丢弃 Spec 均不如独立 Specialist 路径，验证了"不同反馈、不同更新"的核心假设。
4. **Specialist 以稀疏编辑带来针对性增益**：APPLY 率在 0%–19% 之间，MMLU-Pro 上完全不干预，说明其贡献来自条件性精修而非均匀改写。
5. **在线演化中持续有效**：SLIFT 在第一轮和第二轮增量训练后均保持领先，且领先幅度进一步扩大。
6. **反馈可用性差异**：MemoryBench 模拟反馈的完全可用率为 97.0%，远高于 WildFB 真实反馈的 50.4%，这解释了 WildFB 上相对有限的域内性能增益。
7. **效率优势**：参数化存储使推理成本不随日志规模增长，低于检索/记忆类方法。

## 七、优点

- **问题建模新颖**：引入"任务相对"的 Fix/Spec/Null 三类角色划分，将反馈学习从"整条信号"细化为"原子组件 + 泛化范围"的联合决策。
- **双适配器设计具有理论启发性**：以互补学习系统的功能特化为依据，从归纳偏置层面分离默认行为整合与条件性精修，避免过度泛化。
- **自监督闭环**：整个监督信号构建完全由冻结主干完成，无需更强教师模型或显式奖励模型，实用性强。

- **方法透明可复现**：完整提示模板、算法伪代码（Algorithm 1）、损失函数、最优配置均公开，代码已发布。

## 八、不足与局限

- **GPU 型号未披露**：无法准确估算绝对训练成本，影响可复现性和横向算力对比。
- **模拟反馈与真实反馈的鸿沟**：MemoryBench 的模拟用户反馈可用性过高，可能高估框架在真实场景的收益；WildFB 真实反馈中 Null 比例更高，SLIFT 在真实场景的增益相对有限。
- **跨策略比较偏差**：WildFB 训练日志来自 GPT 系列模型，与被评估骨干分布不匹配，可能低估或混淆适配效果。
- **Specialist 的适用范围依赖启发式判定**：SPEC 组件的"是否适用"由冻结主干基于任务与响应的可观察线索判断，泛化到全新任务类型时可能不够稳健；"未观察到的用户偏好"边界也可能导致误判。
- **通用能力评估覆盖有限**：WildFB 训练后仅评估了四个基准，未覆盖代码生成、多轮对话、指令鲁棒性等更多能力维度；MMLU-Pro 的"持平"不能完全排除其他任务上的能力退化。
- **离线日志的 off-policy 偏差**：Generalist 使用的离线近似仅给出梯度偏差界（式 31），未做重要性加权校正；日志响应与当前策略分布差异较大时，蒸馏效率可能下降。
- **应用限制**：Fix/Spec/Null 的三分类依赖提示模板的稳定性；在高度噪声或对抗性用户反馈场景下，分解与角色判定的可靠性需要进一步验证。
