## 摘要
大语言模型智能体的记忆已趋同于一种架构模式：将经验存储为文本、嵌入、反思或规则；在推理时检索；让通用编排器解释该做什么。本文认为，这种模式对于个性化而言是错误的默认选择。我们将肌肉记忆——将重复出现的用户意图编译为专用专家智能体的实践——定位为一种区别于检索的记忆范式，并主张在现有助手对用户施加多轮负担（即反复纠正格式、深度和范围以获得领域合适的答案）的工作负载中，编译是更合适的选择。我们通过参考实现和实证证据支持这一立场。该实现是一个四阶段流水线（采集→分析→增强→评估），挖掘对话历史，区分行为模式与任务模式，并生成带有两阶段触发匹配的质量门控可执行编译专家。在涵盖五个用户画像的90个保留场景中，增强后的助手在专家触发的36个案例中赢得32个，胜率为88.9%，个性化增益为+2.05，而在1-4量表上的准确性损失仅为-0.28。我们讨论了为何在该机制中编译比检索更合适，该结果对更广泛的记忆设计空间意味着什么，以及仍有哪些开放问题。

## Abstract
Memory for LLM agents has converged on a single architectural pattern: store experience as text, embeddings, reflections, or rules; retrieve at inference time; let a general-purpose orchestrator interpret what to do. This paper argues that the pattern is the wrong default for personalization. We position Muscle Memory - the practice of compiling recurring user intent into purpose-built specialist agents - as a distinct memory paradigm from retrieval, and we argue that compilation is a better fit for the workloads where current assistants impose a multi-turn tax on their users: making them repeatedly correct format, depth, and scope to obtain a domain-appropriate answer. We support the position with a reference implementation and empirical evidence. The implementation is a four-phase pipeline (Harvest $\rightarrow$ Analyze $\rightarrow$ Augment $\rightarrow$ Evaluate) that mines conversational history, separates behavioral from task patterns, and emits quality-gated executable compiled specialists with two-stage trigger matching. On 90 held-out scenarios across five user personas, the augmented assistant wins 32 of 36 cases where a specialist fires, an 88.9% win rate, with a +2.05 personalization gain and only a $-0.28$ accuracy cost on a 1-4 scale. We discuss why compilation is better suited than retrieval in this regime, what the result implies for the broader memory design space, and what open problems remain.

## 1. 核心问题与整体含义

- **背景**：当前LLM智能体的记忆系统已收敛为单一架构模式——**存储经验（文本/嵌入/反思/规则）→ 推理时检索 → 让通用编排器（orchestrator）解释并执行**。无论是RAG、MemGPT、Reflexion、A-Mem还是Voyager，本质上都是这种"检索-解释"模式。
- **核心问题**：这种模式对**个性化**而言是错误默认。通用助手无法记住用户的长期偏好，导致用户每次都要花费3-4轮额外对话来纠正格式、深度和范围——作者称之为 **"多轮税"（multi-turn tax）**。例如，资深工程师想要简洁代码式回复，咖啡店主需要无术语的分步指导，但系统每次都返回相同的通用输出。
- **核心论点**：对话历史不应仅被**检索**，还应被**编译（compile）**——将重复出现的用户意图转化为**可执行的专用专家智能体（compiled specialists/mini-agents）**。类比人类肌肉记忆：弹钢琴从刻意控制变为自动化反射，智能体也应将重复模式从"有意识推理"转为"自动执行"。
- **范式对比**：检索式记忆要求编排器在上下文窗口内做更多推理工作；编译式记忆则将编排器从关键路径上移除，其角色简化为**触发匹配与委派**。

## 2. 方法论：核心思想与关键技术

### 核心思想（三原则）

- **P1: 编译优于检索**——跨会话重复出现的模式是稳定工作负载的证据，应编译为代码而非每次推断时重新推导。
- **P2: 专家优于通才**——专用智能体（自身有专属prompt、模型参数、多步蓝图）优于被塞入同等指令的通才编排器。
- **P3: 部署前必须测试**——编译产物是工件，可经过质量门控（critic passes、事实核查、held-out评估）后才上线；检索式记忆的行为仅在推理时浮现，难以审计和回归测试。

### 四阶段流水线（Harvest → Analyze → Augment → Evaluate）

**阶段1: Harvest（历史采集）**
- 生成250个合成多轮对话，覆盖5个用户人设（软件工程师、市场经理、ML研究生、咖啡馆主、旅行/烹饪爱好者）。
- 每人设50个预定义场景，含4种跟进策略（澄清、深挖、转向、纠正）。
- 双LLM编排：用户代理（temperature 0.9，保证多样性）与标准助手交互，产生自然的偏好表达模式。

**阶段2: Analyze（模式分析与智能体群生成）**——八阶段流程：

1. **模式提取与分类**：按批次（10个会话）由LLM识别重复模式（频率≥3），Jaccard相似度（>0.5）合并重叠意图；关键设计是**区分任务模式（用户要什么）与行为模式（用户如何沟通）**——行为模式被统一编译到共享风格文件（user_style.json），避免风格信号误触发任务智能体。
2. **智能体生成**：任务模式编译为可执行Python模块，分为静态型（单次LLM调用）和动态型（多步流水线，如诊断→推荐→格式化）。
3. **六重质量门控**：①并行生成两个候选（温度0.2/0.35）由轻量LLM择优；②生成后事实核查（低置信断言添加不确定性说明）；③critic对真实历史校验10项标准，7/10及格，若≥2处矛盾则上限4/10；④非参数排序（价值×3、区分度×2、触发清晰度×2、质量×2、频率×1，≥25/50保留）；⑤重叠合并（嵌入余弦+Jaccard≥0.73触发merge-or-keep决策）；⑥mini-eval在6个历史场景验证，准确率<2.5或零触发率的被剪枝。
4. **触发预计算**：为每个智能体预计算768维范围嵌入（text-embedding-005）和3-5个对比式二值问卷问题。

**阶段3: Augment（运行时增强）**

- **两阶段触发匹配**：
  - **阶段1（嵌入+软惩罚）**：一次LLM调用提取结构化特征（领域、任务类型、特异性、关键词、动作-对象），嵌入后与所有智能体计算余弦相似度，域不匹配罚-0.15、任务类型不匹配罚-0.10；阈值≥0.45的进入阶段2。使用软惩罚而非硬过滤，保持跨域请求的召回率。
  - **阶段2（二值问卷消歧）**：仅当多个候选存活时触发，3-5个问题是/否在并行LLM调用中评估；组合分数=40%嵌入+60%问卷匹配率；≥0.8者胜出，多个超阈值取最高，无达标者调用更强LLM决胜。问卷阶段对区分语义相似的智能体至关重要（如咖啡馆主的5个同域agent）。
- **任务自适应风格阻尼**：复杂任务（财务规划、定价策略）自动覆盖风格约束（如"bite-sized"偏好），保留语气和语言水平但允许完整交付。
- **幻觉防护（三层）**：生成期critic将捏造引用/技术声明判为0分并剪枝；运行时仅对第一轮消息做正则扫描（检测"as we discussed"等伪造上下文标记）并回退基线；多轮对话中跳过检查以避免误伤。

**阶段4: Evaluate（评估）**——见下节实验设计。

## 6. 主要结论与发现

- **触发时显著胜出**：36个触发场景中32胜4负0平，**胜率88.9%**；个性化得分从1.67提升至3.72（**+2.05**），准确率从3.92降至3.64（**−0.28**，1-4量表）。
- **零成本用户**：user_2（市场经理，6个agent，10-0全胜，个性化+2.50且准确率零损失）和user_4（咖啡馆主，6-0全胜）表现最佳——前者任务域分离清晰，后者需要通用助手经常违背的强格式偏好。
- **个别用户成本集中**：user_1（软件工程师）被过度剪枝为单一agent，准确率损失−1.00；技术领域（API语法等）是幻觉重灾区，如统计agent将`use_continuity`误写为`continuity=True`。
- **误报分析**：不同域场景误报率20%（8/40），但增强助手在误报中仍赢5/8，说明误报通常不具破坏性。
- **一般性论断**：编译更适合个性化（高重复、需要跨实例一致性、可从历史发现规律），检索仍适合一次性事实查询；正确系统应为混合式（编译+检索+知道何时用何者的路由器）。

## 7. 优点与亮点

- **范式创新**：明确提出编译式记忆作为检索之外的"一等公民"记忆范式，类比人类肌肉记忆，视角新颖且具有理论说服力。
- **行为/任务模式分离**：是一项有洞察力的设计决策，有效避免了风格线索引发任务agent误触发的问题，具有普遍借鉴意义。
- **两阶段触发匹配**（嵌入+问卷）优雅地平衡了召回与精度，尤其问卷调查解决语义相似agent的消歧难题。
- **多层质量门控**将"可测试性"作为核心原则落地，从生成到部署多道关卡，体现了类似软件工程的严谨态度。
- **任务自适应风格阻尼**解决了个性化（风格约束）与任务完整性（复杂内容需完整交付）之间的张力。
- **评估协议比静态基准更真实**：模拟用户驱动多轮对话、双助手对称对比，是比单轮LLM-as-judge更严格的方法。
- **代码开源**，提供可复现的参考实现。
- **诚实披露局限**（合成数据、单模型族、静态trigger、无跨用户迁移等），讨论部分质量较高。

## 8. 不足与局限

- **实验覆盖有限**：全合成环境（模拟用户+LLM裁判），无真人用户参与；90场景样本量小，尤其用户级结论统计功效不足；未与RAG、MemGPT、Reflexion等方法做直接对比，没有验证"编译优于检索"的相对优势（只有有无系统的对比）。
- **模型偏差风险**：生成、匹配、评估均用同一模型族（Gemini），跨模型泛化性未验证；LLM裁判未做位置/长度偏差消除，可能与生成系统存在偏好一致性。
- **技术域准确率短板**：API/语法类知识幻觉未解决；现有质量门控只验证通用事实性，不验证领域API正确性；作者建议工具增强验证（沙箱执行代码）但未实现。
- **架构局限**：agent触发规则生成后静态不变，无法适应偏好漂移；无跨用户模式迁移（相似角色用户各自建独立agent群）；覆盖不足的用户（user_1）会被过度剪枝。
- **幻觉防护有限**：运行时仅靠正则匹配常见句式，覆盖面有限，且限定首轮消息，对多轮中的伪造声明缺乏防御。
- **成本评估不完整**：论文仅做了架构层面的推理式成本对比（固定vs随上下文增长），未做实证的延迟/token成本测量。
- **潜在应用限制**：本文方法本质上需要大量历史交互积累模式（频率≥3），冷启动场景效果存疑；真正的部署还需要考虑隐私（将对话编译成agent）、模型更新后agent重验证、并发多agent资源开销等工程问题。
