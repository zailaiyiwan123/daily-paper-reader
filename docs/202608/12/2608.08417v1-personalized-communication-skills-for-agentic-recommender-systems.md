## 摘要
智能体推荐系统越来越多地采用基于大语言模型的用户智能体，在推荐交付前通过模拟反馈评估候选项目。然而，现有用户智能体通常基于有限的个人历史孤立推理，可能导致视角狭窄：智能体从局部不完整的视角评估候选，忽视相关的偏好维度，从而产生不准确的判断。缓解这一问题的一种自然方式是引入其他用户作为顾问智能体，其多样化的历史提供了互补证据，帮助目标用户重新考虑被忽视的偏好信号。然而，通用的用户-顾问沟通过程是不够的，因为不同的用户决策状态需要不同形式的外部建议。基于这一洞见，我们提出了AgentCom，一个用于智能体推荐系统的个性化沟通技能框架。AgentCom将可复用的沟通技能组织成共享的“为什么-做什么-如何-谁”技能库：为什么识别需要沟通的决策缺陷，做什么指定信息任务，如何确定顾问交互协议，谁检索能够执行该协议的顾问。为使共享技能库在使用时个性化并随时间适应，AgentCom引入了两种互补机制：个性化技能路由和失败驱动的技能演化。个性化技能路由通过为每个用户和推荐上下文依次选择合适的技能来构建沟通路径。失败驱动的技能演化从失败的沟通案例中学习，并丰富共享技能库，增加可复用的技能以解决先前未覆盖的沟通需求。实验表明，AgentCom在传统推荐器、社交推荐器和智能体推荐器上均持续提升了推荐性能。

## Abstract
Agentic recommender systems increasingly employ large language model-based UserAgents to evaluate candidate items through simulated feedback before recommendations are delivered. However, existing UserAgents typically reason in isolation based on limited personal histories, which may lead to perspective narrowing: the agent evaluates candidates from a local and incomplete view, overlooks relevant preference facets, and consequently produces inaccurate judgments. A natural way to alleviate this problem is to introduce other users as advisor agents, whose diverse histories provide complementary evidence that helps the target user reconsider overlooked preference signals. Nevertheless, a generic user-advisor communication process is insufficient, as different user decision states require different forms of external advice. Based on this insight, we propose AgentCom, a personalized communication skill framework for agentic recommender systems. AgentCom organizes reusable communication skills into a shared why--what--how--who skill bank: why identifies the decision deficiency that necessitates communication, what specifies the information task, how determines the advisor interaction protocol, and who retrieves advisors capable of executing that protocol. To make the shared skill bank personalized at use time and adaptive over time, AgentCom introduces two complementary mechanisms: personalized skill routing and failure-driven skill evolution. Personalized skill routing constructs a communication path by sequentially selecting suitable skills for each user and recommendation context. Failure-driven skill evolution learns from unsuccessful communication cases and enriches the shared bank with reusable skills that address previously uncovered communication needs. Experiments show that AgentCom consistently improves recommendation performance across traditional, social, and agentic recommenders.

## 1. 论文的核心问题与整体含义

- **研究背景**：智能体推荐系统（Agentic Recommender Systems）通常利用基于大语言模型（LLM）的用户智能体（UserAgent）来模拟用户反馈，并在推荐结果正式交付前对候选项目进行评估。这种模式相比传统一次性预测范式，提供了在结果生成后验证偏好推断的机会。
- **核心问题**：现有 UserAgent 往往基于用户自身有限的历史交互记录进行**孤立推理**，容易产生“视角窄化”（Perspective Narrowing）问题——即从局部、不完整的视角评估候选，忽略其他相关偏好维度，导致推荐判断不准确。
- **整体含义**：本文提出通过**引入其他用户作为顾问智能体（Advisor Agents）**，利用多样化历史提供互补证据，帮助目标用户重新审视被忽略的偏好信号。其核心洞见是：不同用户的决策状态需要不同形式的外部建议，因此沟通不应该是同质化、固定流程的，而应**个性化、可复用、可演化**。

## 2. 论文提出的方法论

### 2.1 核心思想

- 提出 **AgentCom** 框架，将智能体之间的沟通建模为**可复用的沟通技能**，并按拉斯韦尔传播模型（Lasswell's communication model）分解为四个可观测的决策层：
  - **why**：识别当前决策缺陷，判断为何需要外部建议；
  - **what**：将决策缺陷转化为具体的信息任务；
  - **how**：确定顾问间交互协议（如单顾问、多顾问合作、多顾问竞争等）；
  - **who**：检索具有相关或互补证据的顾问。
- 采用“共享技能库 + 个性化路由 + 失败驱动演化”的整体架构。

### 2.2 沟通技能库

- 技能库表示为 `B_r = {B_why, B_what, B_how, B_who}`，每个维度内节点按层级组织。
- 每个技能节点定义为三元组 `s = (c_s, a_s, o_s)`：
  - `c_s`：适用条件；
  - `a_s`：可执行指令；
  - `o_s`：输出契约（保证输出的一致性和可用性）。
- 父子节点关系支持一般技能的特殊化，兄弟节点表示同一沟通需求下的替代策略。

### 2.3 个性化技能路由

- 公共技能库全局共享，但每个用户根据自身上下文动态选择沟通路径。
- 每轮推荐中，UserAgent 先形成初始判断 `q(0)`，路由基于判断和历史上下文，依次为 `what`、`how`、`who` 层生成条件排序列表，选择第一个满足适用条件的节点，构建完整路径 `p_u,t = (s_why, s_what, s_how, s_who)`。
- 不同用户可以使用相同公共技能但走不同路径。

### 2.4 失败驱动的技能演化

- 当最终推荐不匹配真实交互目标时（`F_u,t = 1`），AgentCom 构造完整失败轨迹，由 LLM 分析器诊断负责失败的层 `ℓ*` 与失败类型：
  - **Skill Update**（技能不充分）：在现有技能下添加一个更具体的子技能；
  - **Skill Generation**（能力缺口）：生成全新技能并作为现有技能的兄弟节点插入；
  - **ReRouting**（路由不匹配）：无需修改技能库，重新选择现有技能并重建下游路径。
- 受影响用户随后基于演化后的技能库重新路由并重新执行沟通。

### 2.5 形式化公式与流程

- 初始判断：`q(0) ~ π_user(· | h_u, C_u,t, M_u,t-1)`
- 顾问选择：`V(k) = SelectAdvisors(u, q(k-1), C_u,t, U\{u})`
- 顾问证据生成：`a(k) ~ π_adv(· | {h_v}_{v∈V}, q(k-1), C_u,t)`
- 目标用户重新决策：`q(k) ~ π_user(· | h_u, C_u,t, M_u,t-1, q(k-1), a(k))`

## 3. 实验设计

- **数据集**：三个公开数据集，涵盖不同领域与社交结构：

  - **Epinions**：产品评论交互 + 信任链接；
  - **LibraryThing**：图书交互 + 读者社交连接。
- **基准（Backbone）**：分三类推荐范式：
  - 传统序列推荐：SASRec；
  - 社交推荐：GBSR；
  - 智能体推荐：AFL、iAgent、MemRec。
- **对比设置**：
  - 所有方法共享同一候选集（由 SASRec 生成），控制上游检索空间；
  - AgentCom 作为增强层叠加到各 backbone 上，对比“原始 vs. +AgentCom”；
  - 评估指标为 **Hit@1**；
  - LLM 统一使用 deepseek-4-flash。

## 6. 论文的主要结论与发现

- **AgentCom 能稳定提升各范式推荐性能**：即使对最强的 MemRec backbone，仍能获得 1.8%~8.4% 的相对提升，说明跨用户沟通与交互记忆互补。
- **结构化四层沟通优于通用对话**：去掉任何一层都会导致性能下降，说明“为什么沟通、沟通什么、如何沟通、与谁沟通”均是不可或缺的环节。
- **失败驱动的技能演化有效**：固定初始技能库会显著降低性能，说明演化机制能发现并弥补初始设计中未覆盖的沟通需求。
- **沟通深度需权衡**：增加用户-顾问交互轮数可提升性能（边际收益递减），但增加顾问内部讨论轮数反而降低性能，说明信息冗余和次要偏好放大可能有害。
- **失败模式识别**：沟通可能过度强化次要偏好，导致把原本正确的初始选择推翻，提示需要在个性化与稳健性之间进一步平衡。
