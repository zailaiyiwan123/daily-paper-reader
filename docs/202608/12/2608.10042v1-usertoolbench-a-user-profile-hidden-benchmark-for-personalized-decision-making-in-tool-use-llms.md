## 摘要
工具使用的大语言模型越来越多地被要求代表用户采取行动，但现有基准通常侧重于画像回忆、风格模仿、通用工具使用或响应层面的个性化。我们引入了UserToolBench，一个用于工具使用大语言模型个性化决策的基准。UserToolBench测试模型是否能够从交互历史中推断潜在的用户偏好，识别何时需要澄清，并在信息不完整的情况下生成与用户对齐的工具调用轨迹。该基准基于经过隐私净化的真实交互痕迹构建，结合了结构化的人物画像、公共API风格的工具生态系统和长视野多轮轨迹。它包括10个用户画像、36个工具集、1065轮对话、170个独特工具，以及涵盖信息缺失、单工具和多工具设置的以评估为重点的任务类型。对强工具使用大语言模型的实验表明，当前模型在个性化委托方面仍存在困难。多工具协调、缺失约束推断和长视野行为一致性仍然是主要瓶颈。这些结果表明，个性化评估应超越询问输出是否听起来像用户特定的，而是询问大语言模型是否为其所代表的用户做出了正确的决策。

## Abstract
Tool-use LLMs are increasingly asked to act on users' behalf, but existing benchmarks usually focus on profile recall, style imitation, generic tool use, or response-level personalization. We introduce UserToolBench , a benchmark for personalized decision making in tool-use LLMs. UserToolBench tests whether a model can infer latent user preferences from interaction history, recognize when clarification is needed, and produce user-aligned tool-call trajectories under incomplete information. The benchmark is built from privacy-sanitized real interaction traces and combines structured persona profiles, public API-style tool ecosystems, and long-horizon multi-turn trajectories. It includes 10 user profiles, 36 tool sets, 1,065 turns, 170 unique tools, and evaluation-focused task types covering lack-of-information, single-tool, and multi-tool settings. Experiments with strong tool-use LLMs show that current models still have difficulty with personalized delegation. Multi-tool coordination, missing-constraint inference, and long-horizon behavioral consistency remain major bottlenecks. These results suggest that personalization evaluation should move beyond asking whether outputs sound user-specific and instead ask whether LLMs make correct decisions for the users they represent.

  - 现有"个性化+工具"类基准（如 PEToolBench、PTBench、ToolSpectrum、ETAPP）虽然结合了用户画像与工具调用，但仍未**同时**满足四项核心要求：可执行工具调用、持久用户画像、长视野推理、真实用户-智能体交互。

## 2. 论文提出的方法论（核心思想、关键技术细节）

### 核心思想

- **个性化决策的形式化定义**：将个性化决策建模为**不完整信息下的序列化工具使用问题**。
  - 参考轨迹生成时模型可见用户画像 \( p \)：
    \[
    y^\star = f_{\text{ref}}(p, h, q, T)
    \]
  - 被评估模型在画像隐藏条件下决策：
    \[
    \hat{y} = f_{\theta}(h, q, T)
    \]
  - 关键是对称性：模型不能直接复制画像，必须从历史交互中**推断**用户的潜在偏好，并在工具调用轨迹中体现。
- **Profile-hidden 评估协议**：参考轨迹在画像可见条件下由生成器构造并经 LLM + 人工双重验证；测试时画像完全隐藏，模型只能依靠交互历史、当前请求和工具架构做出决策。

### 数据合成流程

1. **用户画像来源**：从隐私净化的真实交互痕迹出发，用 LLM 辅助抽象为结构化人物画像（含人口学描述、沟通风格、偏好类别、任务习惯、约束条件等），脱敏后保留决策相关信号。
2. **工具生态来源**：基于公共 API 风格能力构建，归一化函数 schema，手工组织成场景级工具集（机票/酒店搜索、天气、安全、娱乐、金融等）。
3. **里程碑式轨迹生成**：给定画像和工具集，逐步生成主题级任务场景；每4个里程碑后将验证过的记录纳入后续历史，产生**跨主题依赖**和**长程偏好一致性**信号。
4. **三类任务类型**：信息缺失（Lack-of-Information, LOI）、单工具（Single-Tool, ST）、多工具（Multi-Tool, MT）。

### 评估指标

- **精确轨迹准确率（Exact Trajectory Accuracy）**：要求工具名称+决策相关参数（单工具）/有序调用序列（多工具）完全匹配参考轨迹；LOI 任务要求正确澄清或正确推断。
- **松弛任务完成准确率（Relaxed Task Completion Accuracy）**：仅要求调用合法工具且达到任务完成状态，允许替代性工具顺序。

## 6. 论文的主要结论与发现

1. **严格个性化委托仍很困难**：最优模型（GLM-5）平均精确轨迹准确率仅 49.36%，无模型过半；
2. **可执行 ≠ 个性化对齐**：DeepSeek V4 Pro 松弛准确率 72.55% 但精确准确率仅 42.49%，GPT-5.4 差值更大（67.71% vs. 31.98%），大量预测虽能完成任务但不符合用户偏好；
3. **多工具协调是最大瓶颈**：平均精确准确率从单工具的 51.30% 降至多工具的 25.24%，错误在调用链中传播累积；
4. **LOI 能力独立于通用工具能力**：GPT-5.4 LOI 得分最高（42.22%）但总体准确率低，Qwen 3.6 Plus 单工具强（58.02%）但 LOI 弱（19.52%）；
5. **历史越长不一定越好**：GPT-5.4 从轨迹前 1/3 的 52.12% 降至后 1/3 的 31.33%，但 Gemini 3.5 Flash 反而上升，说明需要选择性信息检索能力；
6. **严格匹配差异多为实质性错误**：序列/依赖错误在失败中占 82.1–96.5%，主要决策偏差（28.8–65.5%）远超轻微偏差（0.3–2.1%）。

## 7. 优点（方法或实验设计上的亮点）

- **"画像隐藏"评估协议创新性强**：将个性化从"直接画像条件"转为"历史驱动的潜在偏好推断"，更贴近真实部署场景；
- **可执行决策作为个性化指标**：用工具选择、参数值、澄清行为和调用顺序作为个性化对齐的高精度代理，超越表面文本风格；
- **长视野跨主题设计**：里程碑式生成机制创造出跨主题依赖和长程行为一致性测试，弥补了单轮任务无法覆盖的短板；
- **多维度诊断体系**：松弛指标 + 错误分类 + 严重程度审计从不同角度交叉验证，承认"单一参考轨迹"局限性并做定性补充；
- **隐私处理规范**：不使用原始对话，抽象为结构化画像，脱敏流程清晰，伦理约束明确；
- **代码与数据开源**：提供完整构建管线和人工验证界面，支持可复现性。

## 8. 不足与局限

- **规模限制**：仅 10 个画像和 300 个主题，覆盖面有限，难以代表群体多样性；动态偏好分割也只有初步结果；
- **合成数据偏差风险**：LLM 辅助合成可能残留提示特定的词汇/语篇规律，与真实用户-助手对话存在差距（如修复行为、犹豫、话题漂移等）；
- **单一参考轨迹问题**：大部分实例只有一个验证参考，精确匹配可能惩罚合法的同效替代轨迹；作者虽通过松弛指标和严重度审计缓解，但未完全解决；
- **工具生态为模拟 API**：不等同于真实世界应用的完整复杂性；
- **画像与工具集相关性局限**：仅 36 个工具集，主要覆盖天气、安全、娱乐、金融、旅行等，缺少更多领域的代表性；
- **高感知风险领域的适用性**：作者明确警示不应将评估结果视为自主部署于医疗、金融、法律等高风险场景的准备度证明。
