## 摘要
随着大语言模型（LLM）智能体演变为个性化伴侣，记忆已成为一项核心能力。然而，LLM面临一个知识利用问题：即使相关用户偏好完全出现在上下文中，它们也可能无法据此采取行动。当智能体在先前分享的用户偏好本应起作用的语境中未能定制其响应时，我们不清楚是模型未能记住该信息，还是记住了但未能使用它。为了隔离这种失效，我们引入了一种解耦评估范式，对同一用户偏好进行配对的“知晓”与“践行”测试。我们跨16个系统和五种记忆架构进行了大规模实验，在三种表达强度级别下评估了1000个偏好。结果显示，“知晓”与“践行”结果之间存在巨大差距：智能体通常能通过用户偏好的回忆测试，但未能在配对的行为场景中反映该偏好。尽管记忆架构缩小了这一差距，但对于健康和治疗相关的偏好，利用仍然特别薄弱，而这些方面的不践行会带来最大的现实世界风险。

## Abstract
As large language model (LLM) agents evolve into personalized companions, memory has emerged as a core capability. However, LLMs face a knowledge utilization problem: they may fail to act on relevant user preferences even when they are fully present in context. When an agent fails to tailor its response in a context where previously shared user preferences should matter, it is unclear whether the model failed to remember that information or remembered it but failed to use it. To isolate this breakdown, we introduce a decoupled evaluation paradigm that administers paired Know and Act tests to the same user preference. We conduct large-scale experiments across 16 systems and five memory architectures, evaluating 1,000 preferences embedded at three levels of expression strength. Our results show a large gap between Know and Act outcomes: agents often pass the recall test for a user preference but fail to reflect that same preference in the paired behavioral scenario. While memory architectures reduce this gap, utilization remains especially weak for health and therapy-related preferences, where failures to act carry the greatest real-world stakes.

- **核心问题**：LLM存在**知识利用问题**——即使相关用户偏好完整出现在上下文中，模型仍可能不按其行事。当智能体未能依据已知偏好调整响应时，无法判断是“**没记住**”还是“**记住了但没用**”。
- **关键动机**：现有研究要么只测回忆（问答式），要么只测行为（个性化响应），**从未对同一条偏好同时测试两种能力**，因此无法定位记忆失效的根源。
- **整体含义**：通过大规模实证揭示“知晓（Know）≠践行（Act）”的普遍性差距，并证明记忆架构的主要价值不仅在于“存得多”，更在于“用得上”，同时暴露健康与治疗类偏好中高风险的应用失效。

## 2. 论文提出的方法论

- **核心思想**：设计**解耦评估范式**，对**同一条用户偏好**配对施测两个独立任务：
  - **Know测试**：直接询问用户偏好（如“我是否有季节性过敏？”），判定模型能否从记忆中召回该信息，输出二值Pass/Fail。
  - **Act测试**：给出一个不提及该偏好的自然场景（如“推荐春季户外活动”），要求模型应基于记忆中的偏好调整行为；通过**配对比较评分**——将带记忆的响应与同一骨干模型的零记忆基线响应对比，由LLM裁判判定前者是否更体现偏好意识。
- **表达强度梯度**：受Rich（1979）显式/隐式区分启发，将同一偏好构造为三种表达版本（非目标块完全共享，仅目标偏好块不同）：
  - **Explicit（显式）**：用户直接陈述偏好作为对话中心；
  - **Incidental（附带）**：偏好嵌入任务型对话（如润色请假邮件时透露花生过敏），需跨上下文阅读理解才能提取；
  - **Inferential（推断）**：偏好从未直接命名，只能从行为线索推断（如描述花粉季节症状、询问不影响睡眠的药片）。
- **增量记忆构建协议**：沿用MemoryAgentBench的注入-查询范式，将对话块逐条通过标准化模板输入各系统的原生管线，而非静态拼接。
- **利用率的定义**：Utilization Rate = Know通过且Act通过的偏好数 / Know通过的偏好数，即“正确记住的偏好中被实际践行的比例”。
- **失败归因方案（Oracle实验）**：对Mem0的Know Pass × Act Fail案例，逐步绕过检索（注入真实对话块）和绕过理解（直接注入偏好文本），将失败分解为**检索失败、理解失败、应用失败**三类。

## 3. 实验设计

- **数据集**：
  - 基于**PersonaMem-v2**，筛选50个persona（覆盖11个文化区域）；每persona采样20条目标偏好，共**1,000条偏好**；
  - 偏好类型配额：刻板印象、反刻板印象、中性、健康/医疗、治疗/情绪五类；
  - 构造150个块序列（50人 × 3表达级别），共**11,955个对话块**、约**455万tokens**，目标与非目标块比例约1:3；
  - 生成1,000对Know/Act测试（问题与场景跨三个表达级别保持不变）。
- **评估系统（16个，5类架构）**：
  - **长上下文基线**：GPT-4o-mini、GPT-4o、Gemini 3.1 Flash、Claude 4.6 Sonnet；
  - **简单RAG**：BM25；
  - **嵌入RAG**：te3-small、te3-large、Qwen3-Embedding-4B；
  - **结构增强RAG**：Mem0、Zep/Graphiti、Cognee、HippoRAG-v2；
  - **代理记忆**：Letta/MemGPT、Self-RAG、MemoryOS、A-MEM。
- **控制变量设计**：所有RAG与代理记忆系统统一使用GPT-4o-mini生成骨干，隔离模型能力差异；temperature=0；RAG top-k统一为10。
- **Judge验证**：人工评估100份Know与100份Act判断（Fleiss κ=0.89/0.82）；GPT-5与Claude Opus 4.6跨模型一致性（Cohen's κ=0.91/0.88）；盲化Act judge验证（200样本，95%一致，κ=0.87）。
- **零记忆基线**：无任何历史上下文时4个生成模型在全部1,000条Know问题上均低于3%正确率，证明Know问题不可靠先验知识作答。

## 6. 论文的主要结论与发现

- **记住不意味着践行**：Know-Act解离在所有架构中普遍存在；最佳系统（Claude 4.6 Sonnet）也仅将约三分之二记住的偏好转化为行为响应；GPT-4o-mini的利用率仅16.3%。
- **表达级别的影响**：
  - 反常地，**Incidental条件下Know准确率最低**（而非更需推理的Inferential），因为附带信息在任务型对话中不突出，难以被标记为值得记忆；
  - **Explicit条件暴露利用瓶颈**：Know很高但Act/利用率显著偏低，Know-Act差距最大；
  - Inferential条件由于对话围绕主题展开，提供了更丰富的语义检索线索，部分恢复Know表现。
- **偏好类型的影响**：Know准确率在各类型间相对均匀，但**利用率差异尖锐**：Health & Medical最低（平均约21%），Therapy & Emotional次低（约28%），尽管后者Know最高——说明瓶颈在利用而非存储；健康与情绪偏好需要更细致的领域推理才能转化为恰当行为，安全后果最严重。
- **记忆架构的价值**：Mem0将GPT-4o-mini的利用率从16.3%提升至54.6%（近三倍），收益主要体现在行为侧而非检索侧，说明有效的记忆架构不只是“取回更多”，而是**以更可行动的形式呈现信息**。
- **模型先验的作用**：GPT-4o-mini骨干在刻板偏好上表现优于反刻板偏好，而记忆增强系统反转此模式——检索到的记忆可覆盖人口先验。
- **失败归因结果**：全部KP-AF案例中，**理解失败占主导（53.0%）**、检索失败30.7%、应用失败16.2%；Explicit条件下检索失败意外地高（48.7%），非显式条件下理解失败占主导（Incidental 69.6%、Inferential 60.9%）；应用失败比例在各表达级别保持稳定（约14.2%–19.0%），反映底层模型在“明知却不用”上的固有天花板。

## 7. 优点

- **解耦评估范式**：首次对同一条偏好配对施测Know与Act，清晰区分“没记住”与“记住了但没用”，方法论上具有原创性。
- **表达强度梯度设计**：将显式/隐式区分细化为三级别（显式、附带、推断），且三个版本共享非目标块与相同测试题，隔离了表达方式的影响。
- **大规模、多架构对比**：16个系统覆盖五类主流记忆架构，统一生成骨干与统一注入协议保证了架构间对比的公平性。
- **Oracle失败归因**：通过渐进绕过检索/理解，将端到端失败定位到具体管线环节，诊断粒度深。
- **严格的评判验证**：人工+跨模型+盲化多层验证judge可靠性；零记忆基线验证测试题不可靠先验回答。
- **敏感的伦理关注**：明确指出健康与治疗偏好上利用失败的安全风险，具有现实警示意义。

## 8. 不足与局限

- **依赖LLM裁判**：Know/Act评分均由GPT-5判断，可能存在系统性偏差（如对长度偏好、对隐性偏好信号的迟钝）；虽经人工与跨模型验证，仍不能完全消除。
- **合成数据局限**：基于PersonaMem-v2的合成persona与对话，缺乏真实用户历史中的话题漂移、矛盾信息与碎片化表达，生态效度有限。
- **检索任务被简化**：每条偏好仅对应一个目标块且非目标块比例约1:3，远低于真实场景的噪音水平；论文承认此设计使Know-Act差距成为**保守下限**、实际部署中间隙可能更大。
- **Act评分设计风险**：Act judge为“非盲”（知道哪个响应带记忆），虽经200样本盲化验证（95%一致，无系统性偏向），仍存在残余偏差风险。
- **健康类偏好操作化有限**：数据集中于食物过敏、花粉过敏等具体、可操作的条件，未涵盖慢性病管理、药物相互作用等更复杂的健康照护场景，可能低估真实世界中利用失败的严重性。
- **超参数未针对系统调优**：统一使用top-k=10等默认配置，可能对某些系统不利（如MemoryOS硬编码all-MiniLM-L6-v2嵌入模型，引入公平性瑕疵）。
- **二值化评判粒度较粗**：Pass/Fail无法反映部分利用、程度性的偏好遵从差异。
