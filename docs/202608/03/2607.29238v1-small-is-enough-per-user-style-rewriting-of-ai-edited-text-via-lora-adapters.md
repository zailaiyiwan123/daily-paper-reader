## 摘要
InMyStyle是一个隐私优先的单用户系统，它调整小型语言模型，在推理时无需指令提示即可将AI编辑的文本重写为符合个人用户写作风格的文本。给定用户的文档后，它使用多个本地辅助LLM构建成对的训练示例，并在0.5B至7B参数的基础模型上微调LoRA适配器。长度感知的生成预算和自动分块支持不同长度的输入。在来自科学论文语料库的219个评估对上，自动综合得分在所有模型大小及贪婪和采样解码下均稳定在0.69 [范围0-1]。这一观察到的平台期表明，对于所测量的重写任务，小模型就足够了，模型大小决定了权衡而非稳定的质量排名。作为次要评估，来自五个LLM评判员的400个评分显示，InMyStyle输出的平均感知AI程度得分比其辅助AI生成的输入低20%以上，而在InMyStyle内部，平均感知AI程度得分随模型大小而降低。

## Abstract
InMyStyle is a privacy first, single user system that adapts small language models to rewrite AI-edited text towards an individual user's writing style without an instruction prompt at inference. Given a user's documents, it uses multiple local helper LLMs to construct paired training examples and fine tunes LoRA adapters on base models ranging from 0.5B to 7B parameters. Length aware generation budgets and automatic chunking support inputs of different lengths. On 219 evaluation pairs from a scientific-paper corpus, the automatic composite score plateaus at 0.69 [scale 0-1] across all model sizes under both greedy and sampled decoding. This observed plateau suggests that small models are sufficient for the measured rewriting task, with model size determining trade-offs rather than a stable quality ranking. As a secondary evaluation, 400 ratings from five LLM judges give InMyStyle outputs a mean perceived AI-ness score over 20% lower than their helper-AI generated inputs, while mean perceived AI-ness scores decrease with model size within InMyStyle.

### 2. 论文提出的方法论

#### 核心思想
InMyStyle通过"**AI-shadow → 用户原文**"配对数据训练LoRA适配器，学习将机器风格文本变换为用户风格的映射函数。推理时无需任何风格指令、示例或检索上下文，只输入待重写的文本本身。

#### 系统流水线

1. **语料准备**：从用户PDF文档中提取文本，分两阶段过滤：
   - 机械清理：Unicode规范化、修复乱码、处理行尾连字符、移除引用标记/页眉页脚/URL等
   - 内容启发式过滤：摒弃表格、列表、公式密集段落、跨页碎片等非连续散文内容

2. **多家族AI-shadow构造**：三个本地辅助LLM（Qwen2.5-3B、Llama-3.2-3B、Phi-3-mini，来自不同模型家族）分别对每段用户原文进行保留语义的改写，产生配对数据。另有两个随机损坏算子：
   - **AI-tell操作符**（概率0.5）：将常用词替换为刻板机器风格词（如use→utilize），或插入公式化框架表达
   - **轻噪声操作符**（概率0.3）：删除少量单词、偶尔调换字符
   - 最终配对输入为：`x_ik = C(h_k(y_i))`，其中C为可选损坏算子组合

3. **防泄漏数据划分**：按源段落标识符分组划分数据集，保证同一源段落的所有变体都落在同一分区，避免目标文本泄漏。形式化表示为：
   `{i : (x_ik, y_i) ∈ D_train} ∩ {i : (x_ik, y_i) ∈ D_eval} = ∅`

4. **LoRA微调**：
   - 冻结基础模型权重，仅在低秩矩阵上训练：`W′ = W + α/r·BA`
   - 使用**响应专用损失**（Response-Only Loss），输入tokens仅作为条件上下文，不参与损失计算：
   `L(φu) = −Σ_(x,y) Σ_t log p_θ,φu(y_t | x, y_<t)`
   - 这个设计至关重要，因为输入本身就是机器风格文本，在目标中建模它会适得其反
   - 支持4-bit QLoRA以降低显存占用

5. **免提示推理**：
   - 输入仅包含待重写段落，无系统消息、无语义指令、无示例展示
   - 长度感知生成预算：`1.5w + 32`个新token（w为输入词数），封顶600 token
   - 超过500词的输入按句子边界自动切块，独立重写后拼接输出

### 6. 论文的主要结论与发现

1. **自动综合得分平台期**：所有4种模型大小×2种解码模式的组合，自动综合Q全部=0.69，无提升趋势。较大的模型在训练损失和评估困惑度上确实更优，但这种优势并未转化为任务层面的综合得分。

2. **"小而足够"结论成立**：0.5B与7B模型在自动指标上可比。模型大小不构成稳定质量排名，而是在训练成本、风格恢复深度、感知AI程度之间的**权衡参数**。

3. **感知AI程度与模型大小负相关**：在InMyStyle内部，IM最小得分随模型增大而降低（0.5B:6.24 → 1.5B:5.80 → 3B:4.93 → 7B:4.45），即7B模型的输出在感知上最接近人类写作。

4. **去AI化有效性**：InMyStyle输出的感知AI程度（5.34）比辅助AI输入（6.85）低22%；人类原文为3.47，开放式生成文本为8.44。

5. **解码策略无一致影响**：采样未在综合得分上超越贪心解码，故推荐使用确定性的贪心解码。

6. **3B模型为实践甜点**：在保持Q=0.69和内容相似度0.94的前提下，训练时间较7B节省47%，感知AI程度为4.93——平衡了性能与效率。

### 7. 优点

- **隐私优先的系统设计**：全流程本地化处理个人文档，无外部API调用，每用户独立适配器存储——真正落实隐私承诺
- **创新的配对数据构造**：利用多个模型家族（而非单一模型）生成AI-shadow变体，配合两种随机损坏算子，有效增加训练数据多样性
- **严谨的防泄漏划分**：段落级分组拆分保证同源段落不跨训练/测试分区，防止模型"记住"目标文本
- **响应专用损失的巧妙设计**：明确区分输入（机器风格）与目标（用户风格），避免模型建模错误的风格分布
- **免指令推理**：推理时不依赖任何风格标签或提示词，实际使用简单直接
- **长度感知机制**：基于输入长度的动态生成预算与自动切块策略，适应不同输入规模
- **受控实验设计**：同一模型家族、同一数据、同一训练配置下的模型大小比较，结论可信度高

### 8. 不足与局限

- **单用户、单语料域**：仅使用一个目标用户的科学论文，无法推广到其他用户、语言、写作量或领域。作者合作者、审稿人、时间跨度等因素的混杂效应无法分离
- **训练数据是合成的**：3个辅助模型家族+人工设计的损坏算子只是对现实AI编辑文本的近似，无法覆盖实践中遇到的全部模式
- **单一架构与配置**：只评测了Qwen2.5家族+秩8+3轮训练的单一设置，无法确认平台期在其他模型/配置下成立
- **自动指标局限**：
  - 作者分类器可能捕捉到通用人机差异而非用户风格
  - BERTScore倾向于奖励保守复制
  - 风格测量画像只捕捉粗略的句法/标点表层特征
  - 综合得分的权重分配（0.40/0.25/0.15/0.15/0.05）为主观设定
- **LLM评判员局限**：评判员之间校准差异巨大（如Mistral将人类文本评为7.67，而Gemini评1.29）；评测基于仅8个源段落，样本代表性有限；IMS类别与其他条件样本量不平衡；评判模型随时间可能变化
- **无人类参与者评估**：感知AI程度来自LLM代理而非真实验证，论文明确表示人类评估留待未来工作
- **平台期可能不完整**：Q=0.69的平台期可能掩盖各模型在单指标上的差异（如0.5B在R指标上实际表现更好，1.5B在C上偏低等），综合指标可能使"小模型足够"的结论过于简化
