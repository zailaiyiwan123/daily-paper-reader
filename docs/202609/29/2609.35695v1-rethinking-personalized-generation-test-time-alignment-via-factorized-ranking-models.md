## 摘要
将大语言模型（LLMs）对齐到多样化的用户偏好，从根本上受到面向单一化用户进行优化的标准对齐范式的阻碍。在本工作中，首先通过实证研究揭示：通过测试时对齐，个性化生成存在巨大的、尚未被利用的性能提升空间。我们证明，个性化生成特别适合 Best-of-N（BoN）等测试时扩展方法，因为它主要可被视为候选匹配问题，而非生成器能力瓶颈。尽管奖励模型原则上可以利用这一空间，但它们在个性化方面校准不佳，且其十亿参数规模使得对大规模候选池进行评分成本高得令人望而却步。为克服这一局限，我们提出一个参数高效的框架，利用百万参数规模的多层感知机（MLP）排序模型。我们的个性化排序模型以最小开销直接复用基础生成器的内部嵌入。通过扩展训练时数据以提供细粒度个性化偏好，这个百万参数排序模型能够准确地对大规模候选池评分，并可无缝引导生成，以降低生成 N 个候选的成本。在涵盖三种个性化生成设置的九个数据集上的大量实验表明，我们的个性化排序模型有效利用了所发现的提升空间，在每个数据集上均优于十亿参数通用奖励模型，而参数量不到其 0.4%，评分延迟低四个数量级。

## Abstract
Aligning large language models (LLMs) to diverse user preferences is fundamentally hindered by standard alignment paradigms that optimize for monolithic users. In this work, empirical studies are first used to reveal the existence of a massive, untapped performance headroom for personalized generation through test-time alignment. We demonstrate that personalized generation is uniquely suited for test-time scaling methods like Best-of-N (BoN) because it can be viewed primarily as a candidate matching problem rather than a generator capability bottleneck. While reward models could in principle exploit this headroom, they are poorly calibrated for personalization, and their billion-parameter scale makes scoring large candidate pools prohibitively expensive. To overcome this limitation, we propose a parameter-efficient framework utilizing million-parameter scale multi-layer perceptron (MLP) ranking models. Our personalized ranking model directly reuses the internal embeddings of the base generator with minimal overhead. By scaling train-time data to provide fine-grained personalized preferences, this million-parameter ranking model accurately scores large candidate pools and can seamlessly guide generation to reduce the cost of materializing N candidates. Extensive experiments on nine datasets spanning three personalized generation settings show that our personalized ranking model effectively exploits the discovered headroom, outperforming billion-parameter generalist reward models on every dataset, with under 0.4% of their parameters and four orders of magnitude lower scoring latency.

- **关键实证发现**：
  - 用 Oracle Best-of-N（BoN）分析发现，基础生成器在给定用户 profile 后，已经能生成与用户参考文本高度匹配的候选；随着候选池 N 增大，Oracle 指标持续上升，未见饱和。
  - 但通用奖励模型（8B 级）作为选择器时，性能在 N=16 左右就趋于平坦，甚至下降；在 N=64 时最多只捕获约 23% 的 Oracle 提升空间，九个数据集中有八个不足 12%。

- **整体含义**：与其为每个用户微调生成器，不如训练一个轻量、个性化、低成本的排序模型，在测试时从生成器已有候选中选出最符合用户偏好的答案。

## 2. 方法论

### 2.1 核心思想：解耦“语言理解”与“偏好评分”

- 生成器已经阅读了 query、用户 profile 和候选回答，其最终层隐藏状态已包含丰富语义。
- 因此不再用独立奖励模型重新编码文本，而是**直接复用生成器的内部嵌入**，用一个百万参数级 MLP 做评分。
- 排序模型在固定特征空间中做回归，语义理解由生成器承担，排序模型只学习“哪个候选最像该用户会写的”。

### 2.2 关键技术细节

- **嵌入复用**：
  - 对 query \(x\)、用户 profile \(u\)、候选回答 \(y_i\)，分别取生成器最终层最后一个 token 的隐藏状态 \(h_x, h_u, h_{y_i} \in \mathbb{R}^d\)。
  - \(h_x, h_u\) 每个 query 只计算一次，并在 N 个候选中共享；\(h_{y_i}\) 随候选生成自然产生。
- **排序头**：
  - 将 \([h_x \| h_u \| h_{y_i}]\) 拼接后输入小型 MLP \(f_\phi\)，输出标量效用 \(\hat r_u(x,y)\)。
  - 默认配置：3 层隐藏层、宽度 256、GELU、dropout 0.1，约 2.8M 参数；另有 1M、3M、10M、30M 等规模。
- **训练目标**：
  - 默认采用 pointwise MSE 回归：
    \[
    \mathcal{L}_{\text{MSE}}(\phi)=\mathbb{E}\left[(f_\phi(h_x,h_u,h_{y_i})-s^*(x,y_i,u))^2\right]
    \]
  - 目标 \(s^*\) 为候选相对用户参考文本的 ROUGE-L，并在每个候选池内做零均值、单位方差标准化。
  - 选择 pointwise 的理由：监督信号是基数型而非仅序数型；BoN 和 guided decoding 需要跨池可比的绝对效用；计算复杂度为 \(O(N)\) 而非 pairwise 的 \(O(N^2)\)。
- **训练数据构造**：
  - 每个训练 prompt 用基础生成器采样 64 个 on-policy 候选，温度 1.0。
  - 每个候选用 ROUGE-L 对用户参考文本打标。
  - 这些候选构成“hard negatives”：语言流畅、主题相关，但风格或语义不符合特定用户，从而迫使排序模型学习细粒度个性化区分。
- **推理方式一：Best-of-N 选择**：
  - 生成 N 个候选，用排序模型评分，取最高分。
- **推理方式二：Ranking Guided Generation（排序引导生成）**：
  - 单次解码，仅在生成器不确定时干预。
  - 用 next-token 熵 \(H_t\) 衡量不确定性；若 \(H_t \le \tau\)，保持原 argmax。
  - 若 \(H_t > \tau\)，计算排序模型对隐藏状态的梯度 \(g_t=\nabla_{h_t}\hat r_u\)，通过 LLM head 投影到词表 \(u_t=Wg_t\)，再以熵调制的步长 \(\alpha_t\) 混合 logits：
    \[
    \ell'_t=\ell_t+\alpha_t u_t,\quad y_t=\arg\max_v \ell'_t
    \]
  - 默认超参：\(\tau=1\)，\(H_{\max}=8\)，\(\alpha_0=5\)，3-token warmup，九个数据集共享。

### 2.3 算法流程（文字版）

1. 用冻结的生成器对每个 prompt 生成候选池，并获取 query、profile、候选的最后层隐藏状态。
2. 用用户参考文本计算每个候选的 ROUGE-L，池内标准化后作为回归目标。
3. 训练小型 MLP 排序模型，输入三向量拼接，输出标量分数。
4. 测试时：
   - 方案 A：生成 N 个候选，排序模型评分选最优；
   - 方案 B：单次解码，在熵高于阈值时用排序模型梯度引导 token 选择。

### 2.4 复杂度优势

- 标准奖励模型选择复杂度：\(O(N \cdot L \cdot d_r^2)\)，与序列长度 \(L\) 和奖励模型维度 \(d_r\) 相关。
- 本文嵌入复用选择复杂度：\(O(N \cdot d^2)\)，与序列长度无关。
- 实测中，2.8M 排序模型评分 64 个候选约 0.098 ms；8B 奖励模型约 2.4 s，延迟差约四个数量级。

## 6. 主要结论与发现

- **个性化 headroom 巨大**：Oracle BoN 随 N 持续上升，说明基础生成器已能产生高度个性化的候选，瓶颈在“选择”而非“生成”。
- **通用奖励模型不适合个性化选择**：8B 通用奖励模型在短文本生成上 N=16 后平坦，在长文本 QA 上甚至不如 N=1；N=64 时最多捕获 23% headroom。
- **百万参数排序模型显著优于通用奖励模型**：在全部九个数据集上，N=64 时均为最佳选择器；随 N 增大持续提升，而通用奖励模型停滞或下降。
- **参数效率极高**：1M–30M 参数范围内性能变化很小（最多约 0.006 ROUGE-L）；2.8M 默认模型已足够。
- **接近微调 8B 奖励模型**：微调 8B 模型仍领先，但 30M 排序模型恢复其 45%–94% 的增益，评分延迟低约四个数量级，且无需为每个数据集微调十亿参数模型。
- **跨指标泛化**：在从未训练的 BLEU 指标下，本文排序模型仍在九个数据集上选择出最高 BLEU 候选，说明学到的是用户偏好匹配，而非单纯拟合 ROUGE-L。
- **引导生成可恢复部分增益**：单次解码加排序引导，在短文本
