## 摘要
大语言模型（LLMs）正日益被期望能够适应个体用户，然而当仅有有限的用户特定样本可用时，有效的个性化仍然具有挑战性。在本工作中，我们采取另一种视角：预训练的LLMs可能已经具备个性化的潜在能力，因此少量用户样本或许就足以以极少的用户特定适配引导模型朝向与用户一致的行为。基于这一视角，我们提出LatentPersonal，一个将个性化建模为在共享潜在适配空间中进行导航的框架。LatentPersonal从少量用户样本中推断出紧凑的潜在表示，以引导用户特定的模型适配，并使用变分信息瓶颈进行正则化，以鼓励紧凑的偏好表示。我们用LoRA实例化LatentPersonal，利用其低秩参数化作为个性化的自然低维适配空间。通过在共享的低秩因子之间简单插入一个用户特定的引导向量，模型可以通过对该紧凑表示的轻量级推断来导航至个性化适配，而无需更新共享的LoRA参数。在多个个性化数据集上的实验表明，LatentPersonal大幅降低了用户特定的适配开销，同时仅凭少量用户特定交互即可实现有效的个性化，并在单样本（one-shot）设置下表现尤为强劲。

## Abstract
Large language models (LLMs) are increasingly expected to adapt to individual users, yet effective personalization remains challenging when only limited user-specific samples are available. In this work, we take an alternative perspective: pretrained LLMs may already possess latent capacity for personalization, and a few user samples may therefore suffice to guide the model toward user-aligned behavior with minimal user-specific adaptation. From this perspective, we propose LatentPersonal, a framework that formulates personalization as navigation in a shared latent adaptation space. LatentPersonal infers a compact latent representation from a few user samples to guide user-specific model adaptation, regularized with a variational information bottleneck to encourage compact preference representations. We instantiate LatentPersonal with LoRA, leveraging its low-rank parameterization as a natural low-dimensional adaptation space for personalization. By simply inserting a user-specific guidance vector between the shared low-rank factors, the model can navigate toward personalized adaptations through lightweight inference of this compact representation, without updating the shared LoRA parameters. Experiments across multiple personalization datasets demonstrate that LatentPersonal substantially reduces user-specific adaptation overhead while achieving effective personalization from only a few user-specific interactions, with particularly strong performance in the one-shot regime.

## 1. 核心问题与整体含义

- **研究背景**：大语言模型（LLM）被期望适应个体用户，但在仅有少量用户特定交互样本时，个性化仍很困难，直接适配容易数据低效且过拟合。
- **现有方法的共同假设**：多数个性化方法（个性化提示、检索增强、用户表示学习、参数高效微调等）都倾向于“用有限用户数据重新学习用户对齐行为”，可能重复学习预训练模型本已支持的行为。
- **本文核心问题**：有效个性化是否真的必须从有限用户信息中重新学习用户特定行为？
- **核心假设**：预训练 LLM 可能已编码与个性化相关的潜在行为，只是未针对特定用户表达出来；少量用户样本足以引导模型走向用户对齐行为，而无需大量用户特定适配。
- **整体含义**：将个性化重新表述为在共享潜在适配空间中的“导航”，而非为每个用户独立学习一套适配参数。

## 2. 方法论

### 2.1 核心思想

- 个性化 = 在共享低维潜在偏好空间中导航。
- 给定预训练模型参数 \(\theta_0\)，用户 \(u\) 的交互数据 \(D_u=\{(x_i,y_i)\}_{i=1}^K\)，引入隐变量 \(z_u\in\mathbb{R}^d\)（\(d\) 远小于参数适配维度）。
- 个性化模型：\(\theta_u=\theta_0+g(z_u)\)，其中 \(g(\cdot)\) 是共享的“隐变量到适配”映射。
- 个性化目标转化为在潜在空间中寻找最优位置：\(z_u^*=\arg\min_z \mathcal{L}(D_u,\theta_0+g(z))\)。

### 2.2 信息瓶颈约束的潜在适配

- 将用户交互划分为支持集 \(D_u^{sup}\) 与不相交的查询集 \(D_u^{qry}\)。
- 理想表示满足“适配充分性”：\(I(D_u^{sup};\Delta\theta_u^*|z_u)=0\)，并尽量压缩交互特异性信息。
- 概念目标：最大化 \(I(z_u;\Delta\theta_u^*)-\beta I(z_u;D_u^{sup})\)，即**适配保留**减去**交互压缩**。
- 由于最优适配 \(\Delta\theta_u^*\) 不可得，使用可处理替代目标：
  - **适配保留项**：用支持集推断 \(z_u\)，经共享映射生成适配，在查询集上计算任务损失 \(\mathcal{L}_{adapt}\)。
  - **交互压缩项**：用变分先验 \(r(z)=\mathcal{N}(0,I)\) 对后验 \(q_\psi(z_u|D_u^{sup})\) 做 KL 正则 \(\mathcal{L}_{comp}\)。
- 总目标：\(\mathcal{L}_{total}=\mathcal{L}_{adapt}+\beta\mathcal{L}_{comp}\)，联合优化偏好编码器 \(q_\psi\) 与共享适配映射 \(g_\phi\)。

### 2.3 LoRA 实例化

- LoRA 更新：\(\Delta W^{(l)}=B^{(l)}A^{(l)}\)，低秩结构天然提供低维适配空间。
- 在共享低秩因子之间插入用户隐变量调制：  
  \(\Delta W_u^{(l)}=B^{(l)}\mathrm{diag}(z_u)A^{(l)}\)。
- 等价于 \(r\) 个共享秩一方向 \(b_i^{(l)}a_i^{(l)T}\) 的用户特定加权组合，\(z_{u,i}\) 控制每个方向贡献。
- 训练时联合学习偏好编码器和共享 LoRA 参数；推理时共享 LoRA 固定，只需从少量交互推断 \(z_u\)，无需用户特定梯度优化。
- 偏好编码器：冻结 LLM 提取交互末层隐状态并均值池化，得到固定维用户表示，再经两层 MLP 预测对角高斯后验的均值与方差。
- 该框架也推广到 **Adapter** 和 **Prompt Tuning**：分别在中层瓶颈维度和软提示 token 维度上插入 \(z_u\) 调制。

## 3. 实验设计

### 3.1 数据集与场景

- **HiCUPID**：面向个性化 AI 助手的对话基准，基于历史对话评估个性化回复生成。
- **PRISM**：人类反馈数据集，通过真实交互捕捉个体偏好，含个性化评分与细粒度反馈。
- **PersonaMem-v2**：长时用户交互下的个性化回复生成，强调隐式用户偏好。
- **PIR（Persona-Iterative-Responses）**：大规模 persona 条件偏好数据集，包含问题、persona 描述与备选回复。

### 3.2 Benchmark 与评估指标

- **ROUGE-1、ROUGE-L、METEOR**：参考生成质量。
- **Content Personalization (CP)**：内容是否对齐用户偏好（话题、例子、强调、顺序等），1–10 分。
- **Presentation Personalization (PP)**：语气、风格、组织、细节、格式等呈现是否匹配用户偏好，1–10 分。
- CP/PP 使用 **gpt-4.1-mini** 作为 LLM 评估器，所有方法统一评估协议。
- 每测试用户使用 1/2/4/8/16 条交互作为支持集，另留 4 条交互用于评估；每个设置至少评估 200 条留出交互。
- 先按用户平均，再跨用户平均；报告 95% 置信区间（mean ± 1.96 SE）。

### 3.3 对比方法

- **Base**：无个性化的冻结基座模型。
- **ICL**：基于用户示例的少样本上下文学习，不更新参数。
- **LoRA**：直接在用户样本上微调 LoRA 参数。
- **PPlug（Persona-Plug）**：学习用户表示并以 personal embedding 条件化生成。
- **Profile-to-PEFT**：用超网络从用户表示生成个性化 PEFT 参数。
- **LatentPersonal**：本文方法，主实验采用 LoRA 实例化。

### 3.4 额外实验

- 消融：w/o Latent、w/o Navigation、w/o IB。
- 敏感性：信息瓶颈系数 \(\beta\) 与潜在维度 \(d_z\)。
- 效率：测试时个性化延迟与生成延迟。
- 潜在空间分析：UMAP 可视化、跨 shot 位移、维度级变异性、跨 shot 对齐、隐变量缩放、用户特异性、用户间插值。
- 跨 PEFT 架构：Adapter、Prompt Tuning 实例化。

## 6. 主要结论与发现

- LatentPersonal 在四个个性化基准上整体表现强，**尤其少样本（1-shot）场景优势明显**。
- 随观察交互增多，与竞争方法的差距通常缩小，说明潜在导航在用户证据有限时最有效。
- 消融表明：移除隐变量、移除信息瓶颈、或将潜在导航替换为直接 LoRA 适配，均导致性能下降，其中移除信息瓶颈退化最大。
- 测试时个性化开销显著低于梯度式 LoRA 适配；1–4 shot 下也低于 Profile-to-PEFT；生成延迟随观察数增加保持相对稳定。
- 学习到的潜在空间具有结构：不同 shot 的表示共享同一潜在结构，随交互增加逐渐稳定；跨 shot 维度保持对齐；用户特定变异集中在部分维度。
- 用户特异性分析：匹配的 \(z_u\) 优于交换、均值、共享 LoRA 条件；用户间插值可平滑转移个性化表现。
- 隐变量缩放显示：\(\alpha=0\) 大幅退化，\(\alpha=1\) 表现强，\(\alpha>1\) 无系统提升甚至退化，说明个性化既依赖方向也依赖位置。
- Adapter 与 Prompt Tuning 实例化也获得提升，说明框架不局限于 LoRA。
- 总体支持“预训练 LLM 已具潜在个性化能力，少量样本可通过潜在空间导航实现轻量适配”的视角。

## 7. 优点

- **视角新颖**：将个性化从“重新学习”转为“共享潜在空间导航”，为少样本个性化提供新范式。
- **方法简洁**：LoRA 实例化只需在共享低秩因子间插入对角调制，结构改动小，无需额外参数生成器。
- **部署高效**：推理时共享 LoRA 固定，仅需前向推断 \(z_u\)，避免用户特定梯度优化，个性化延迟低。
- **正则化合理**：引入变分信息瓶颈，兼顾适配充分性与交互压缩，鼓励紧凑偏好表示。
- **实验较全面**：覆盖多数据集、多 backbone、多 shot、多指标、消融、敏感性、效率、潜在空间分析和跨 PEFT 架构。
- **分析深入**：UMAP、位移、跨 shot 对齐、缩放、用户特异性与插值等分析，为“导航”解释提供多维实证。
- **评测公平性较好**：统一评估器、统一协议、用户不相交、支持/查询分离。

## 8. 不足与局限

- **来源未区分**：无法判断潜在个性化结构是继承自预训练，还是在群体级个性化训练中涌现。
- **评估范围有限**：聚焦基准式少样本个性化，未研究长期、演化中的用户偏好行为。
- **LLM 评估风险**：CP/PP 由 gpt-4.1-mini 评分，可能存在评估偏差或不稳定，尽管使用了确定性评估和统一提示。
- **算力报告不足**：仅说明单张 A100，未报告训练时长、总卡数、总成本等。
- **对比方法有限**：未纳入 OPPU、TAPPER、PerFit 等，作者虽给出设置不同的解释，但缺少更广基线。
- **潜在空间共享范围有限**：每个 benchmark 独立训练共享潜在空间，未验证跨异构数据集共享。
- **超参数与规模**：LoRA rank 固定 16、batch size 1、潜在维度默认 16，未系统探索更大规模或更长训练。
- **生成延迟**：LatentPersonal 生成延迟略高于部分基线（如 PPlug），虽然稳定，但未展示大规模服务场景下的吞吐表现。
- **应用限制**：方法依赖支持集与查询集划分进行训练，实际部署中用户交互可能更嘈杂、非独立同分布，泛化性仍需验证。
