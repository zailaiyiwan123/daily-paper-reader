Abstract 

In this reproducibility study, we investigate the transparency and scrutability of recommender systems enhanced by incorporating generated natural-language user profiles that represent user preferences. The original paper explores the synthesis of user profiles from raw user-generated review text across domains such as movies and accommodations (Amazon Movies & TV, TripAdvisor). Crucially, these natural-language user profiles enable direct user in-teraction and intervention, allowing users to customize recommendations by correcting mis-attributed preferences or addressing cold-start settings. We successfully reproduce the core findings of the original study. Additionally, we extend the evaluation by conducting system-atic context ablation experiments, multi-seed stability across five distinct random seeds to establish statistical reliability, and a mechanis-tic interpretability analysis using the nnsight 

framework to probe internal model represen-tations under counterfactual profile perturba-tions. Our findings verify the original pa-per’s claim that User Profile Recommendation (UPR) achieves competitive performance un-der its test-set reranking protocol and makes recommendations more transparent. Perturb-ing the natural-language profiles does change predictions, but it shifts predicted ratings uni-formly across genres with no detectable genre-selective effect, leaving rankings unchanged even under direct activation steering. We trace this back to the rating-regression objective rather than the profile interface, with ranking-objective models clearly exceeding in this task. 

1 Introduction 

Recommender systems have increasingly transi-tioned from the classical content-based and col-laborative filtering paradigms to Large Language Model (LLM)-driven architectures (Deldjoo et al., 2024). While classical approaches represent users as dense, uninterpretable latent vectors, recent work by Ramos et al. (2024) introduces User Profile Rec-ommendation (UPR). UPR synthesizes a user’s past review history into a natural-language summary profile. This textual representation allows users to inspect, scrutinize, and directly modify their own profiles to customize future recommendations. In this work, we present a comprehensive repro-duction and extension of the UPR methodology. We evaluate the framework on the Amazon Movies & TV (He and McAuley, 2016) and TripAdvisor 1

(Li et al., 2021) datasets, investigating both the rec-ommendation accuracy and the semantic properties of the generated user profiles. 2

Our primary contributions are as follows:

End-to-End Reproducible Pipeline: We provide a fully reproducible codebase locked with uv

Protocol Alignment & Comparison: We evalu-ate non-LLM baselines in Cornac (Salah et al., 2020) under standardized evaluation protocols matching the LLM evaluation script, present-ing side-by-side benchmark tables comparing original published numbers with our reproduc-tion.

2 Background & Methodology 

2.1 Problem Formulation 

Let U denote the set of users and I denote the set of items. Each user u ∈ U has an associated interaction history Eu = {eu, 1, e u, 2, . . . , e u, |Eu|},where eu,i represents a written review for an item i

previously consumed by u, and is often considered an explanation of a rating yu,i . The UPR approach consists of two primary stages depicted in Figure 1: 1. Profile Generation: An LLM (e.g., Llama 2-7B or Mistral-7B) synthesizes the review history Eu into a concise, natural-language user profile Pu:

Pu = LLM_Gen (Eu) (1) 2. Recommendation / Rating Prediction: Asequence classification model fθ is fine-tuned to predict item relevance ˆyu,i given the user profile Pu and the item metadata Ii:

ˆyu,i = fθ(Prompt (Pu, I i)) (2) 

2.2 User Scrutability & Interventions 

Unlike black-box latent vector embeddings hu ∈

Rd, the natural-language profile Pu is human-readable. Users can edit Pu directly by removing incorrectly inferred preferences (e.g., removing a dislike for a specific subgenre) or inserting new preference constraints (e.g., adding an interest in horror movies). 

3 Scope of Reproduction & Extensions 

3.1 Scope of Reproduction 

Our reproduction focuses on validating the core claim of Ramos et al. (2024): that natural-language user profiles can match or exceed the predictive performance of raw review histories while main-taining human interpretability and scrutability. We reproduce fine-tuning of the recommender LLM fθ

and baseline evaluations on the Amazon Movies & TV and TripAdvisor datasets using open-weight Llama2-7B (Touvron et al., 2023) and Mistral-7B (Jiang et al., 2023) profile generations. We made sure to reuse the profiles generated by Ramos et al. (2024), to ensure an adequate and fair comparison. 

3.2 Extensions Beyond the Original Paper 

We extend the original study in three key directions: 1. Context Ablation Study: We systemati-cally evaluate model performance under three user representations ( user profile , review history , and item-review history ) paired with two item metadata representations ( item title and item title and description ). 2. Multi-Seed Robustness: To ensure that re-ported gains are not artifacts of favorable ran-dom initializations, we conduct 5-seed stabil-ity trials on the Amazon dataset. 3. Mechanistic Interpretability & Scrutabil-ity: We leverage the nnsight interpretability library (NDIF Team, 2024) to probe internal model activations, map profile embeddings via UMAP, score cluster key terms via gradi-ent attributions, and track latent representation trajectories under counterfactual user profile perturbations. 

4 Experimental Setup 

4.1 Datasets & Preprocessing 

We utilize the preprocessed Amazon Movies & TV dataset and the TripAdvisor dataset, both formatted into the standard train.jsonl ,

validation.jsonl , and test.jsonl splits. Com-prehensive details on data splits, prompt templates, fine-tuning configurations, hardware, and evalua-tion protocols are provided in Appendix A. 

4.2 Baseline Models & Protocol Alignment 

To ensure fair comparison, we evaluate several standard recommendation baselines using Cornac (Salah et al., 2020): MostPop , UserKNN , ItemKNN ,

MF , and NeuMF .We aligned the baseline evaluation script (rec_baselines.py ) with the LLM evaluation protocol ( evaluate.py ). Exact metric formulas and candidate pool definitions are detailed in Ap-pendix A.

Three checks precede any null: a zero vector and a constant vector are both exact no-ops (layer nor-malization removes the latter, so steering directions must be non-uniform), while a random direction is not. Additive steering of the final representa-tion cannot be selective at all, since the linear head shifts every item by the same α(w·d); we therefore steer at blocks 2, 6 and 9, early enough to interact with item tokens through attention. The result dissociates representation from behav-ior (Table 8 in Appendix B). The probe readout moves as intended, from P (crime )=0 .064 at α=0 

to 1.000 at α≥4 – a complete reversal of apparent genre preference – while crime items’ mean rating 

falls slightly ( 3.999 → 3.984 ) and their mean rank shifts by at most 0.2 of 330 positions at every layer. The probe reversal is partly guaranteed by construc-tion, since the injected direction is the class-mean difference the probe reads; the behavioral null is the finding. 

5.4.3 Does the model personalize at all? 

These nulls admit a simpler explanation: there may be no personalization signal to steer. For each of the 200 users, we rank one held-out pos-itive item against 99 items they have not inter-acted with, using identical never-interacted can-didate sets for each ranker. The task is feasible on this data with a ranking-objective model, as Weighted Matrix Factorization (WMF) achieves 

0.806 . The profile model reaches only 0.542 

with titles ( p=0 .047 ) and 0.510 with descriptions (p=0 .62 ), below MostPop (0.697 ), which person-alizes not at all (Table 7). Its scores are uncorre-lated with item popularity (Spearman’s r = −0.03 

to −0.08 , n.s. ), even though the positives are far more popular than the distractors ( 81 .6 versus 41 .9

training interactions). The ordering identifies the cause. While the ranking-objective model WMF reaches 0.806 ,rating-regression objectives reach 0.51 –0.55 . Ev-ery training pair is an item the user chose and re-viewed, so the data holds no mismatched user–item pairs from which a content-matching rule could be learned, and the loss is minimized by a user offset plus an item offset – the structure of Table 5. This is consistent with the metrics in §5: test-set rerank-ing over the Sakai condensed list orders only items the user already selected, for which item-side pri-ors suffice. The limitation is thus a property of the rating-regression objective, inherited from the orig-inal formulation, rather than of natural-language profiles as an interface.

6 Discussion on Reproducibility 

What was easy? The conceptual framework of UPR is intuitive, and the availability of pre-processed interaction datasets and initial source code provided a valuable starting point to repro-duce the original paper’s findings. 

What was hard? Replicating the results required modifying the codebase to fix several issues: Syn-tax & Variable Errors: The original codebase contained a few broken variable references and undeclared identifiers. Missing Environment Def-initions: No requirements.txt or environment locks were supplied. We fixed this by introduc-ing a clean uv environment specification. Evalua-tion Split Issue: The original code validated the model using the test split instead of the validation split. Correcting this to ensure the test split is used only during testing yielded metric values closely aligned with the reported numbers. Baseline Proto-col Realignment: Original baseline scripts evalu-ated models under mismatched candidate protocols. Standardizing all baselines in rec_baselines.py 

resolved this discrepancy. 

7 Conclusion 

This paper reproduces transparent and scorable rec-ommendations using the UPR method developed by Ramos et al. (2024) and extends it to new con-text configurations, random seeds for robustness checks, and mechanistic interpretability for prob-ing the model activation space with counterfactuals. Our reproduction study confirms that the natural-language user profiles generated by UPR are both useful for the final recommendation task and in-crease the transparency and scrutability of the rec-ommendation model. This enables users to better understand the recommendations provided to them and modify the suggested user profile, steering pre-dictions towards a state that better reflects reality. Limitations 

Our reproduction study focuses on the Amazon Movies & TV and TripAdvisor datasets, and evalu-ates profiles synthesized via the Llama2-7B model. While our mechanistic interpretability analysis confirms structured feature representations in la-tent space, exploring profile stability under varied prompt templates and open LLM generation set-tings remains an important area for future research. Furthermore, our steering validation experiments reveal an important issue with the regression ob-jective of the loss function, as it inherently dimin-ishes the model’s ability to rank items. A natural next step is to explore a ranking objective to assess whether the user-profile bottleneck allows mean-ingful steering of user predictions based on their interests.

A.2 Fine-Tuning Configuration & Hyperparameters 

In the codebase ( train.py ), recommendation scor-ing is framed as sequence classification fine-tuning. The model (fθ) is instantiated via Hugging-Face’s AutoModelForSequenceClassification 

initialized from pretrained causal LM back-bones, defaulting to gpt2 (124M param-eters) or open-weight instruction models (meta-llama/Llama-2-7b-chat-hf and 

mistralai/Mistral-7B-Instruct-v0.1 ), with a single scalar output regression head (num_labels=1 ). • Model Initialization & Tokenizer Setup: 

Loaded via HuggingFace’s AutoTokenizer .Tokenizer padding is configured to right-side (padding_side="right" ) with sequence truncation enabled (truncation=True ,

padding="max_length" ), capped at amaximum sequence length of 300 tokens (max_length=300 ). The padding token is ex-plicitly mapped to the end-of-sequence token (pad_token = eos_token ), and model config is aligned via model.config.pad_token_id = model.config.eos_token_id .• Target Normalization & Inverse Transfor-mation: Ground-truth user rating scores y ∈

[1 , 5] are linearly normalized to [0 , 1] during dataset tokenization via yscaled = ( y − 1) /4.During evaluation, model scalar logit outputs 

ˆs ∈ [0 , 1] are transformed back to the original rating scale via ˆy = ˆ s · 4 + 1 .• Optimizer, Learning Rate & Precision: 

Fine-tuning uses the AdamW optimizer with a linear learning rate decay schedule (lr_scheduler_type="linear" ). The ini-tial learning rate is set to η = 3 × 10 −4

(0.0003 ). Computation runs in full precision (FP32 / FP16 depending on CUDA hardware capability). • Batching, Epochs & Checkpoint Strategy: 

Effective per-device batch size is set to 64 (per_device_train_batch_size=64 ,

per_device_eval_batch_size=64 ). Fine-tuning runs for up to 5 epochs with epoch-wise evaluation and check-pointing (save_strategy="epoch" ,

eval_strategy="epoch" ). Only the single best checkpoint is re-tained (save_total_limit=1 ,

load_best_model_at_end=True ). Early stopping is monitored via 

EarlyStoppingCallback with patience of 3 evaluation epochs (patience=3 ,

threshold=0.0 ). Unused dataset columns are stripped during batch collation (remove_unused_columns=True ). • Random Seeds: Deterministic ran-dom initializations are enforced via set_random_seeds(seed) across PyTorch, NumPy, and Python random . Baseline reproduction uses seed 42, while multi-seed robustness tests evaluate seeds 37, 38, 39, 40, and 41.
